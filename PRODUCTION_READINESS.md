# PRODUCTION_READINESS.md — security and privacy readiness checklist

**This is a checklist for a deployment, not a claim about this prototype.** The prototype processes only synthetic data and is **not production-ready**: most of the controls below are account or organisation controls that no repository can enforce. Each row says what exists *today*, and what production must add *before any real customer data, any real STR, or any claim of production readiness*.

The table is rendered from [`skills/readiness.py`](skills/readiness.py) (`PRODUCTION_CHECKLIST`) by `python3 scripts/render_readiness_docs.py --write`; `tests/test_readiness.py` fails if it drifts. It is also shown in the app (*Tools · Architecture & readiness → Security and privacy readiness*).

Status vocabulary: **Implemented and demonstrated** (built and exercised by the offline tests) · **Prototype simulation** (a stand-in is named) · **Production requirement** (not built; cannot honestly be simulated).

## How to read it

* **Authenticated user identity.** The decision-maker is the Snowflake session identity when the runtime supplies one (`st.user["user_name"]` inside Streamlit-in-Snowflake); a typed ID is recorded as **not authenticated** and the stored gate carries `IDENTITY_NOT_AUTHENTICATED`. Streamlit's local-development placeholder e-mail is ignored (an earlier build pre-filled the officer's ID from it). The ledger `INSERT` also stamps `written_by_user` (`CURRENT_USER()`) and `written_by_role` in the database, so the attribution does not rest on the client alone. What the hosted runtime returns for `st.user` and `CURRENT_USER()` has **not been verified in Snowsight**.
* **Approved-model allow-list.** `skills/core.py` `APPROVED_MODELS`. A configured model that is not on the list, or whose name is not a plain identifier, fails closed: nothing is sent, the officer decides without AI. The account still allows every model (`CORTEX_MODELS_ALLOWLIST = ALL`); production should set the account-level list to match.
* **Prompt minimisation.** A test proves a customer reference, the alert metadata, the transaction-owner map and the session identity never reach a prompt. The KYC profile line and counterparty names still do, verbatim — with real data that needs pseudonymisation first.
* **Separation of duties.** Today one person holds the owner, app and ACCOUNTADMIN roles (SECURITY.md §8). The audit role and the outcome-feed writer are designed as distinct roles but are opt-in and not provisioned.
* **What this document does not cover:** a penetration test, a Streamlit content-security-policy review, supply-chain scanning and incident-response runbooks. The measured state of the Snowflake account (no network policy, no MFA, no resource monitor) is in [SECURITY.md §8](SECURITY.md).
